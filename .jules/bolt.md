## 2024-04-16 - [Lazy Loading Heavy UI Components]
**Learning:** Heavy UI components like `EmojiPicker` can significantly impact the initial bundle size and load time. They should be lazy-loaded using `next/dynamic` to optimize performance. When using `next/dynamic` for UI components that affect layout, it is critical to provide a loading placeholder with matching dimensions (e.g., `h-[23rem] w-80`) to prevent layout shifts. Furthermore, if a component relies on client-side data or has hydration mismatches (like the emoji dataset), `ssr: false` should be used.
**Action:** When implementing or optimizing heavy UI components that are not immediately visible (e.g., inside dropdowns or popovers), always consider dynamic importing. Ensure `ssr: false` is used if hydration issues arise, and always provide a strictly sized loading skeleton/placeholder to maintain layout stability.
