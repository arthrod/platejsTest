## 2024-04-15 - [Lazy Loading Next.js Components in Playwright UI Tests]

**Learning:** When using `next/dynamic` to lazy load components with a fallback placeholder, Playwright UI testing against a Next.js dev server may require an extremely long wait time on the first render because it triggers Next.js' on-demand Fast Refresh compilation for that chunk. Also, when waiting for Radix UI popovers that contain lazy-loaded components, you can wait for `[data-radix-popper-content-wrapper]` instead of internal selectors of the unmounted component. Additionally, Next.js telemetry warnings during `pnpm build` or uncleaned artifacts (dev.logs) can result in failed Code Reviews.
**Action:** Always clean up dev/test artifacts (`dev.log`, `verify_*.py`, test screenshots/videos) before requesting Code Review. When testing a dynamically loaded component with Playwright against a development server, allocate at least `15000ms` of timeout _after_ interacting with the trigger, and capture intermediate screenshots if the final assertion times out. Wait for Radix UI wrappers like `[data-radix-popper-content-wrapper]` to confirm the dropdown is open.
